# ლისი ველი

სამეზობლოს რეესტრი — ნაკვეთები, მფლობელები, საკონტაქტო ინფორმაცია.
ცხრილისა და ინტერაქციული რუკის სახით.

71 ნაკვეთი, 8 ქუჩა. სამი დონის წვდომა: **მაცხოვრებელი** (ხედავს), **მოდერატორი**
(ასწორებს საკონტაქტო ველებს და ზარის პასუხებს), **ადმინი** (ამტკიცებს
მომხმარებლებს და ცვლის როლებს). გადახდის ჩაწერა ცალკე დგას: მას მხოლოდ
პროექტის **ხაზინდარი** და ადმინი ეხება — ვინც ფულს წერს, ის აგებს პასუხს ჯამზე.

## არქიტექტურა

- **ინტერფეისი:** სტატიკური საიტი GitHub Pages-ზე, build-პროცესის გარეშე
- **ბაზა:** Supabase (Postgres) — ექვსი ცხრილი, RLS-ით დაცული
- **ავტორიზაცია:** Supabase Auth, Google provider
- **სერვერი:** არ არსებობს

ბრაუზერი პირდაპირ ელაპარაკება Supabase-ს `anon` გასაღებით. შუამავალი
სერვერი აღარ არის — უფლებებს RLS იცავს, აუდიტს ტრიგერი წერს,
ოპტიმისტურ ბლოკირებას თავად `UPDATE` ასრულებს.

`anon` გასაღები `js/config.js`-ში ღიად წერია და ასეც არის განკუთვნილი:
ექვსივე ცხრილზე RLS ჩართულია და არაავტორიზებულ როლს `GRANT`-იც კი არ
აქვს. ორი დამოუკიდებელი ბარიერი.

## ტესტები

    node --test tests/*.test.js
    python3 tools/test_import.py -v

**`node --test tests/` (საქაღალდის ფორმა, glob-ის გარეშე) ამ ტიპის მანქანებზე
გატეხილია** — Node-ი დირექტორიას მოდულის გზად კითხულობს და `MODULE_NOT_FOUND`-ს
აგდებს. ყოველთვის გლობით გაუშვი: `tests/*.test.js`.

npm-პაკეტები არ არის საჭირო — არც ტესტების გასაშვებად, არც აპლიკაციისთვის,
არც სერვერისთვის.

ერთადერთი გარე დამოკიდებულება ერთჯერად იმპორტის სკრიპტს აქვს:
`tools/import.py`-ს `.xlsx`-ის წასაკითხად სჭირდება Python-ის `openpyxl`
(`python3 -m pip install --user openpyxl`). ის მხოლოდ `build/*.csv`-ების
თავიდან ასაწყობად არის საჭირო — იხ. `docs/setup.md`, Step 3.
