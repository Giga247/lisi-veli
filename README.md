# ლისი ველი

სამეზობლოს რეესტრი — ნაკვეთები, მფლობელები, საკონტაქტო ინფორმაცია.
ცხრილისა და ინტერაქციული რუკის სახით.

71 ნაკვეთი, 8 ქუჩა. სამი დონის წვდომა: **მაცხოვრებელი** (ხედავს), **მოდერატორი**
(ასწორებს საკონტაქტო ველებს), **ადმინი** (ამტკიცებს მომხმარებლებს და ცვლის როლებს).

## არქიტექტურა

- **ინტერფეისი:** სტატიკური საიტი GitHub Pages-ზე, build-პროცესის გარეშე
- **სერვერი:** Google Apps Script Web App
- **ბაზა:** Google Sheet (პირადი, არასაჯარო)
- **ავტორიზაცია:** Google Identity Services + ID token-ის შემოწმება (`aud`-ის ჩათვლით)

მონაცემი მოძრაობს ასე: ბრაუზერი → `fetch` `text/plain`-ით (არა `application/json` —
Apps Script CORS preflight-ს არ პასუხობს) → Apps Script Web App → Google Sheet.
Sheet არავისთვის არ არის გაზიარებული და არც „Published to web" — მასთან წვდომა
მხოლოდ სკრიპტს აქვს („Execute as: Me"), ხოლო სკრიპტი ყოველ მოთხოვნას ტოკენით
ამოწმებს, სანამ Sheet-ს ხელს ახლებს.

## ფაილების რუკა

| საქაღალდე | რა არის |
|---|---|
| `index.html`, `css/` | გვერდის ჩონჩხი და სტილი |
| `js/` | ფრონტენდი — `lib.js` (სუფთა ლოგიკა, ტესტირებადი), `auth.js`, `api.js`, `table.js`, `map.js`, `admin.js`, `main.js`, `ui.js`, `config.js` |
| `apps-script/` | სერვერის კოდი — `Code.js` და `lib.js` ჩასასმელია Apps Script რედაქტორში, იხ. `docs/setup.md` |
| `tools/` | ერთჯერადი სკრიპტები: `import.py` (`.xlsx` + `.geojson` → `build/*.csv`), `fetch_osm.py` (OSM → `data/plan.geojson`), `render_plan.py` (→ `data/plan.svg`, შესვლის ეკრანის ნახაზი)
| `tests/` | Node-ის ტესტები `apps-script/lib.js`-ისა და `js/lib.js`-ისთვის |
| `docs/` | დოკუმენტაცია (იხ. ქვემოთ) |

`js/config.js` ერთადერთი ადგილია, სადაც Client ID და Web App URL იწერება — ორივე
საჯარო მნიშვნელობაა (Client ID Google-ის დიზაინითაა ღია, Web App URL კი ტოკენის
გარეშე არაფერს აბრუნებს), მაგრამ **დეპლოის წინ ორივე პლეისჰოლდერიდან რეალურ
მნიშვნელობაზეა შესაცვლელი** — იხ. `docs/setup.md`.

## ტესტები

    node --test tests/*.test.js
    python3 tools/test_import.py -v

**`node --test tests/` (საქაღალდის ფორმა, glob-ის გარეშე) ამ ტიპის მანქანებზე
გატეხილია** — Node-ი დირექტორიას მოდულის გზად კითხულობს და `MODULE_NOT_FOUND`-ს
აგდებს. ყოველთვის გლობით გაუშვი: `tests/*.test.js`.

npm-პაკეტები არ არის საჭირო — არც ტესტების გასაშვებად, არც აპლიკაციისთვის,
არც სერვერისთვის.

ერთადერთი გარე დამოკიდებულება ერთჯერად იმპორტის სკრიპტს აქვს:
`tools/import.py`-ს `.xlsx`-ის წასაკითხად სჭირდება Python-ის `openpyxl`
(`python3 -m pip install --user openpyxl`). ის მხოლოდ `build/*.csv`-ების
თავიდან ასაწყობად არის საჭირო — იხ. `docs/setup.md`, Step 0.

## დოკუმენტაცია

- `docs/setup.md` — განთავსების ინსტრუქცია ნულიდან: CSV-ების აწყობა, Google
  Sheet, OAuth, Apps Script, Deploy, `js/config.js`, GitHub Pages
- `docs/qa-checklist.md` — ხელით შესამოწმებელი სცენარები დეპლოის შემდეგ
- `docs/superpowers/specs/` — საწყისი სპეციფიკაციები (ეტაპი 1 და დაგეგმილი ეტაპი 2)
- `docs/superpowers/plans/` — ეტაპი 1-ის იმპლემენტაციის გეგმა, ამოცანებად დაყოფილი
- `docs/chat-logs/` — სესიების ავტომატური ლოგი (იხ. `CLAUDE.md`)

## მდგომარეობა

ეტაპი 1-ის მთელი კოდი დაწერილია და ტესტირებულია, მაგრამ **ჯერ არ არის
განთავსებული.** `js/config.js`-ში ორივე მნიშვნელობა კვლავ პლეისჰოლდერია —
სანამ ისინი შეივსება, საიტი შესვლას არ ცდილობს და ეკრანზე ამას პირდაპირ წერს.
რეესტრის ცოცხლად დასაყენებლად გაიარეთ `docs/setup.md`, შემდეგ
`docs/qa-checklist.md` — ეს უკანასკნელი გეტყვით, მუშაობს თუ არა სისტემა
რეალურად, სანამ 70 მეზობელს მოიწვევთ.
