## 1. მიზანი

უბნის მაცხოვრებლების რეესტრი — ნაკვეთები, მფლობელები და საკონტაქტო ინფორმაცია — ხელმისაწვდომი ცხრილისა და ინტერაქციული რუკის სახით, სადაც ქუჩების მოდერატორებს მონაცემების განახლება შეუძლიათ, დანარჩენ დამტკიცებულ მაცხოვრებლებს კი ნახვა.

### წარმატების კრიტერიუმი

პროტოტიპი წარმატებულია, თუ:

1. მაცხოვრებელი Google-ით შედის, ადმინი ამტკიცებს, და ის ხედავს 71 ნაკვეთს ცხრილშიც და რუკაზეც
2. მოდერატორი ცვლის ტელეფონის ნომერს და ცვლილება ჩანს ყველასთვის და ჩაწერილია ლოგში
3. ნაკვეთი, რომელსაც პოლიგონი აკლია, მაგრამ კოორდინატი აქვს, რუკაზე მარკერით აღინიშნება
4. ბაზა (Google Sheet) არასოდეს არის საჯაროდ ხელმისაწვდომი — მხოლოდ აპლიკაციის გავლით

### რატომ ასე

**GitHub Pages სერვერს ვერ უშვებს** — მხოლოდ სტატიკურ ფაილებს არიგებს. იქ ჩადებული ნებისმიერი გასაღები საჯაროა. ამიტომ ყველა გადაწყვეტილება — „ვინ ხარ", „რა გაქვს უფლება", „ეს მონაცემი ვალიდურია თუ არა" — სერვერზე მიიღება.

**სერვერის როლს Google Apps Script Web App ასრულებს.** ის უფასოა, მომხმარებლის Drive-ში ცხოვრობს, და Sheet-თან წვდომა აქვს მფლობელის უფლებებით. Sheet თავად არავისთვის არ არის გაზიარებული.

## 4. ავტორიზაცია — კრიტიკული ტექნიკური გადაწყვეტილება

### პრობლემა

Apps Script Web App-ს ორი განთავსების რეჟიმი აქვს და ორივეს ხარვეზი აქვს:

| რეჟიმი | Sheet-ის უსაფრთხოება | მომხმარებლის იდენტიფიკაცია |
|---|---|---|
| „Execute as: Me" | ✅ Sheet პირადი რჩება | ❌ `Session.getActiveUser().getEmail()` ცარიელს აბრუნებს სხვა დომენის Gmail ანგარიშებისთვის |
| „Execute as: User accessing" | ❌ მომხმარებელს Sheet-ზე წვდომა სჭირდება | ✅ მეილი სანდოა |

ორივე გამოუსადეგარია: პირველი ვერ გვეუბნება ვინ არის, მეორე კი ბაზას აღებს.

### გადაწყვეტა — ID token-ის შემოწმება

1. **ფრონტენდი** იყენებს **Google Identity Services**-ს (`accounts.google.com/gsi/client`). მომხმარებელი შედის, ბრაუზერი იღებს **ID token**-ს (ხელმოწერილი JWT, რომელშიც წერია მეილი).
2. **ყოველი მოთხოვნა** ამ ტოკენს თან ატანს.
3. **Apps Script** ტოკენს ამოწმებს `https://oauth2.googleapis.com/tokeninfo?id_token=...` მისამართზე `UrlFetchApp`-ით.
4. სკრიპტი აუცილებლად ამოწმებს:
   - `aud` **ზუსტად ემთხვევა** ჩვენს Client ID-ს — *ამის გარეშე ნებისმიერი Google აპლიკაციის ტოკენი გამოდგებოდა*
   - `iss` არის `accounts.google.com` ან `https://accounts.google.com`
   - `email_verified` არის `true`
   - `exp` ჯერ არ გასულა
5. მხოლოდ ამის შემდეგ ეძებს მეილს `მომხმარებლები` ფურცელში და არკვევს როლს.

**განთავსება:** „Execute as: Me", „Who has access: Anyone". უსაფრთხოებას ტოკენის შემოწმება უზრუნველყოფს, და არა Apps Script-ის წვდომის პარამეტრი. Sheet პირადი რჩება.

**Client ID საჯაროა** — ეს Google-ის დიზაინით ასეა და პრობლემას არ ქმნის. მისი ბოროტად გამოყენება იბლოკება „Authorized JavaScript origins" პარამეტრით, სადაც მხოლოდ ჩვენი GitHub Pages მისამართი იქნება ჩაწერილი.

**ქეშირება:** ვერიფიცირებული ტოკენის შედეგი ინახება `CacheService`-ში ტოკენის SHA-256 hash-ის გასაღებით, ვადით 5 წუთი. ეს ამცირებს დაყოვნებას განმეორებით მოთხოვნებზე.

### CORS — მეორე ტექნიკური დეტალი

Apps Script Web App **preflight `OPTIONS` მოთხოვნას არ ამუშავებს**. ამიტომ ყველა გამოძახება უნდა იყოს **„simple request"**:

- მეთოდი: `POST`
- `Content-Type: text/plain;charset=utf-8` (და **არა** `application/json`)
- სხეული: JSON სტრიქონი, რომელსაც სკრიპტი `JSON.parse(e.postData.contents)`-ით კითხულობს
- მორგებული header-ები აკრძალულია (ტოკენი სხეულში მიდის, არა `Authorization` header-ში)

## 5. მონაცემთა მოდელი

ბაზა არის ერთი Google Sheet, სამი ფურცლით. სათაურები **ქართულადაა** (რომ ხელით რედაქტირება მოხერხებული იყოს), კოდი კი მათ ინგლისურ გასაღებებზე გადაიყვანს ერთი მაპინგის ცხრილით `lib.js`-ში. სვეტების **თანმიმდევრობა მნიშვნელობა არ აქვს** — ძებნა სათაურის სახელით ხდება.

|---|---|---|---|

| N | `num` | ტექსტი | სახლის ნომერი |
| სრული მისამართი | `address` | ტექსტი | |
| ფართობი კვ.მ | `area` | რიცხვი | |

| სახელი | `first_name` | ტექსტი | |
| გვარი | `last_name` | ტექსტი | |

### ფურცელი `მომხმარებლები`

| ქართული სათაური | გასაღები | ტიპი |
|---|---|---|
| მეილი | `email` | ტექსტი, **უნიკალური**, lowercase |
| როლი | `role` | `admin` / `moderator` / `member` / `pending` / `blocked` |
| ქუჩა | `street` | ტექსტი — მოდერატორის ქუჩა |
| სახელი გვარი | `display_name` | ტექსტი |
| საკადასტრო კოდი | `cad` | ტექსტი — რომელი კომლია. ეტაპი 2 ამას იყენებს, რომ მაცხოვრებელმა საკუთარი ვალდებულება დაინახოს |

| დამამტკიცებელი | `approved_by` | მეილი |

`street` ველი v1-ში მხოლოდ საინფორმაციოა — მოდერატორი მთელ ბაზას არედაქტირებს. ის იმიტომ ინახება, რომ მოგვიანებით შეზღუდვის ჩართვა ერთი პირობის დამატება იყოს.

## 6. API

ერთი endpoint: `POST {APPS_SCRIPT_URL}`

**მოთხოვნის სხეული:**
```json
{ "idToken": "eyJ...", "action": "plots", "payload": { } }
```

**პასუხი — წარმატება:**
```json
{ "ok": true, "data": { } }
```

**პასუხი — შეცდომა:**
```json
{ "ok": false, "error": "FORBIDDEN", "message": "ამ მოქმედების უფლება არ გაქვთ" }
```

### მოქმედებები

| action | ვისთვის | აღწერა |
|---|---|---|
| `me` | ყველა შესული | აბრუნებს `{email, role, street, display_name}` |
| `requestAccess` | `pending`/უცნობი | ქმნის `pending` ჩანაწერს; იდემპოტენტურია; ადმინს უგზავნის მეილს |
| `plots` | `member`+ | ყველა ნაკვეთი მასივად |
| `updatePlot` | `moderator`+ | ცვლის მითითებულ ველებს |
| `users` | `admin` | მომხმარებლების სია |
| `setRole` | `admin` | ანიჭებს როლს და ქუჩას |
| `logs` | `admin` | ბოლო N ჩანაწერი ლოგიდან |

### `updatePlot` დეტალურად

```json
{
  "action": "updatePlot",
  "payload": {
    "cad": "99.99.99.002",
    "expected_updated_at": "2026-08-20T14:03:11.000Z",
    "fields": { "phone": "+995599123456", "first_name": "ზურაბ" }
  }
}
```

`expected_updated_at` **სავალდებულოა**. თუ Sheet-ში სხვა მნიშვნელობაა, ბრუნდება `CONFLICT` — ე.ი. სხვამ ამასობაში შეცვალა. ფრონტენდი აჩვენებს „ჩანაწერი სხვამ შეცვალა, გადატვირთეთ".

ჯერ არასოდეს განახლებული ჩანაწერისთვის `განახლდა` სვეტი ცარიელია — ამ შემთხვევაში `expected_updated_at` უნდა იყოს ცარიელი სტრიქონი `""`. `null`-ის ან ველის გამოტოვების შემთხვევაში ბრუნდება `VALIDATION`, რომ შემთხვევითი გადაფარვა გამოირიცხოს.

**რედაქტირებადი ველები (მოდერატორი და ადმინი):** `first_name`, `last_name`, `phone`, `street`, `num`, `address`, `area`, `purpose`, `note`

**არასოდეს რედაქტირებადი აპლიკაციიდან:** `cad` (პირველადი გასაღები), `geometry`, `lat`, `lon` (გეოგრაფიული მონაცემი გარე წყაროდან), `updated_at`, `updated_by` (სისტემური). სიის გარეთ ნებისმიერი ველი იწვევს `FORBIDDEN`-ს — თეთრი სია, არა შავი.

წერა LockService-ის გლობალურ ბლოკირებაშია გახვეული (`LockService.getScriptLock()`, 10 წამის მოცდა), რომ პარალელურმა ჩაწერებმა ერთმანეთი არ გადაფარონ.

### შეცდომის კოდები

| კოდი | HTTP-ის ანალოგი | ქართული შეტყობინება |
|---|---|---|
| `UNAUTHENTICATED` | 401 | გთხოვთ შეხვიდეთ Google-ით |
| `PENDING` | 403 | თქვენი მოთხოვნა დამტკიცების პროცესშია |
| `BLOCKED` | 403 | წვდომა შეზღუდულია |
| `FORBIDDEN` | 403 | ამ მოქმედების უფლება არ გაქვთ |
| `NOT_FOUND` | 404 | ჩანაწერი ვერ მოიძებნა |
| `VALIDATION` | 400 | არასწორი მონაცემი (დეტალი `message`-ში) |

## 8. ფრონტენდი

## 10. უსაფრთხოების წესები

1. **Sheet არასოდეს არ ქვეყნდება.** არც „Publish to web", არც „Anyone with the link". მხოლოდ მფლობელი. წვდომა მხოლოდ Apps Script-ის გავლით.
2. **არანაირი საიდუმლო repo-ში.** `config.js`-ში მხოლოდ Client ID და Apps Script URL — ორივე დიზაინით საჯაროა.
3. **`aud`-ის შემოწმება სავალდებულოა.** ამის გარეშე ნებისმიერი Google აპლიკაციის ტოკენი მიიღებოდა. ეს ერთი შემოწმებაა მთელი მოდელის საყრდენი.
4. **Authorized JavaScript origins** — მხოლოდ GitHub Pages-ის მისამართი. ლოკალური ტესტირებისთვის დროებით `http://localhost:8080`, რომელიც პროდაქშენში იშლება.
5. **როლი ყოველ მოთხოვნაზე მოწმდება სერვერზე.** ფრონტენდზე ღილაკის დამალვა მხოლოდ მოხერხებულობაა, არა დაცვა.
6. **ლოგი უცვლელია** — მხოლოდ დამატება, არასოდეს რედაქტირება ან წაშლა აპლიკაციიდან.
7. **პერსონალური მონაცემები.** ტელეფონები ყველა დამტკიცებულს უჩანს. ეს შეგნებული გადაწყვეტილებაა. მაცხოვრებელს, რომელსაც არ სურს ნომრის გამოჩენა, ველი ცარიელი რჩება.
8. **ლოკალურ საცავში (localStorage) ტოკენი არ ინახება** — მხოლოდ მეხსიერებაში, გვერდის სესიის განმავლობაში.

**რას ნიშნავს ეს პრაქტიკულად:** გვერდის გადატვირთვისას ტოკენი ქრება. Google Identity Services ამას ჩუმი ხელახალი შესვლით ავსებს (One Tap) — მომხმარებელი, რომელსაც ბრაუზერში Google-ში შესული აქვს, ხელახლა ღილაკს არ აჭერს. თუ ჩუმი შესვლა ვერ მოხერხდა, ჩნდება „შესვლა Google-ით" ღილაკი. ID token-ის სიცოცხლე ერთი საათია; მისი გასვლისას API აბრუნებს `UNAUTHENTICATED`-ს და `js/auth.js` ერთხელ ავტომატურად ითხოვს ახალს და მოთხოვნას იმეორებს. ორჯერ ვერ მოხერხების შემთხვევაში ჩნდება შესვლის ღილაკი.

## 11. ტესტირება

### სერვერის მხარე — `apps-script/lib.js` + `node --test`

Apps Script-ს ტესტ-რანერი არ აქვს და Sheet-ზე მიბმული კოდი ლოკალურად ვერ გაიშვება. ამიტომ **ყველა ლოგიკა, რომელიც გადაწყვეტილებას იღებს, `lib.js`-შია** — სუფთა ფუნქციები, რომლებიც Sheet-ს, ქსელს და Apps Script-ის API-ს არ ეხებიან. `Code.js` მხოლოდ „მილია": კითხულობს Sheet-ს, ეკითხება `lib.js`-ს რა ქნას, წერს უკან.

`lib.js` ორივე გარემოში მუშაობს — Apps Script-ში `module` განუსაზღვრელია და ექსპორტის ბლოკი გამოტოვდება, Node-ში კი `require`-ით იტვირთება. ეს იძლევა **რეალურ წითელ-მწვანე ციკლს** ლოკალურად:

```
node --test tests/
```

npm-პაკეტები არ არის საჭირო — Node-ის ჩაშენებული რანერი და `node:assert` საკმარისია.

სავალდებულოდ დასაფარი სუფთა ფუნქციები:

| ფუნქცია | ტესტის შემთხვევები |
|---|---|
| `normalizePhone` | `599123456` → `+995599123456`; `+995 599 12-34-56` → იგივე; `abc` → შეცდომა; `''` → `''` |
| `parseGeometry` | სწორი პოლიგონი → კოორდინატები; ცარიელი უჯრა → `null`; დაზიანებული JSON → `null` და გაფრთხილება ლოგში, **გამონაკლისის გარეშე** |
| `editableFields` | `phone` ნებადართული; `geometry`, `lat`, `lon`, `cad` უარყოფილი |
| `checkRole` | `member` ვერ ცვლის; `moderator` ცვლის; `admin` ყველაფერს; `pending` ვერაფერს |
| `mapHeaders` | ქართული სათაურები → გასაღებები; არეული თანმიმდევრობა; ნაკლული სვეტი |
| `verifyTokenClaims` | სწორი `aud`; არასწორი `aud`; `email_verified: false`; გასული `exp` |
| `diffFields` | ლოგისთვის სწორი ძველი/ახალი წყვილები; უცვლელი ველი არ იწერება |

**`verifyTokenClaims` ცალკე ფუნქციად გამოიყოფა ქსელური გამოძახებისგან** სწორედ იმიტომ, რომ ტესტირებადი იყოს. `Code.js`-ის `verifyToken` ქსელს ელაპარაკება და ქეშირებას აკეთებს; გადაწყვეტილებას `lib.js` იღებს.

`Code.js`-ის გადამოწმება ხდება (ა) Apps Script-ის რედაქტორში `smokeTest()`-ის გაშვებით, რომელიც Sheet-იდან წაკითხულს ბეჭდავს, (ბ) განთავსებული endpoint-ის `curl`-ით შემოწმებით არასწორი ტოკენით — უნდა დაბრუნდეს `UNAUTHENTICATED`.

### ინტეგრაციული — ხელით, სცენარებით
