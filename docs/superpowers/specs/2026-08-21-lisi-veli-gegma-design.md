## 1. მიზანი

ორი ერთმანეთთან დაკავშირებული ცვლილება.

**პირველი — სახელი.** პლატფორმას დღეს „კედრის უბანი" ჰქვია. ეს სახელი ერთ ქუჩას
ასახელებს, მაშინ როცა რეესტრში რვა ქუჩაა და ტერიტორია ქვემო ლისია. ახალი სახელია
**„ლისი ველი"**.

**მეორე — მთავარი გვერდის სახე.** დღეს შესვლის ეკრანი შიშველი ტექსტია: სათაური და
Google-ის ღილაკი. მისული მეზობელი ვერ ხვდება, რომ ეს მისი უბნის სისტემაა.
ამის ნაცვლად ეკრანზე უბნის საკუთარი ვექტორული გეგმა უნდა იდგეს — გზები, ქუჩები,
საკადასტრო კონტურები ჩადგმული ნაგებობებით და მისამართების წარწერებით.

იგივე ნახაზი აპლიკაციის შიგნით „რუკა" ტაბსაც ჩაანაცვლებს: დღევანდელი OpenStreetMap-ის
ტაილები გაქრება და მათ ადგილს ჩვენი გეგმა დაიკავებს.

### წარმატების კრიტერიუმი

1. `localhost:8080`-ზე შესვლის ეკრანი ხსნის „ლისი ველს" და უბნის გეგმას აჩვენებს —
   ავტორიზაციამდე, სერვერზე ერთი მოთხოვნის გარეშე
2. გეგმაზე იკითხება ქუჩების სახელები და ნაკვეთების მისამართის ნომრები
3. „რუკა" ტაბი იმავე გეგმას აჩვენებს, ოღონდ ცოცხალი მონაცემით: ქუჩების ფერადი
   კოდირება, პოპაპები, რედაქტირების ღილაკი — ყველაფერი, რაც დღეს მუშაობს
4. ნახაზი იკითხება ღია და ბნელ თემაში ერთნაირად
5. Leaflet აღარსად იტვირთება

## 2. მოცულობის საზღვრები

### შედის

- ყველა მომხმარებელზე ხილული წარწერის შეცვლა „ლისი ველზე"
- OSM-იდან ნაგებობებისა და გზების ერთჯერადი მოქაჩვა რეპოში ჩასაკომიტებელ ფაილში
- გზებისთვის ქუჩის სახელების მიწერა ჩვენი ნაკვეთების მონაცემიდან

### არ შედის

ხატვის ინსტრუმენტი · გეომეტრიის რედაქტირება ბრაუზერში · ტაილების ჰიბრიდი ·

ფაილებისა და რეპოს გადარქმევა

**ფაილების სახელები უცვლელი რჩება.** `4_Kedri_Street`, `კედრის_ქუჩა_ნაკვეთები.geojson`,

## 4. მონაცემთა არხი

### 4.1 `tools/fetch_osm.py`

ერთხელ ხელით გასაშვები სკრიპტი, `tools/import.py`-ის პატერნით: ქსელი სკრიპტშია,
ლოგიკა ცალკე მოდულში.

```
python3 tools/fetch_osm.py            # ჩაწერს data/plan.geojson-ს
python3 tools/fetch_osm.py --dry-run  # მხოლოდ დათვლა, ჩაწერის გარეშე
```

**bbox:** `41.7430, 44.7165, 41.7480, 44.7225` — ნაკვეთების საზღვრებს ყოველი მხრიდან
~150 მ ეყრდნობა, რომ ნახაზი კიდეებზე მოულოდნელად არ წყდებოდეს.

**Overpass query:**

```
[out:json][timeout:100];
(
  way["building"](41.7430,44.7165,41.7480,44.7225);
  way["highway"](41.7430,44.7165,41.7480,44.7225);
);
out geom;
```

მოსალოდნელი შედეგი (2026-08-21-ის შემოწმებით): **83 შენობა**, **~66 გზა**.
გზების კლასები: `service` 23, `footway` 18, `residential` 13, `track` 3,
`construction` 3, `secondary` 2, `proposed` 2, `path` 2.

`construction` და `proposed` **გამოირიცხება** — ეს არარსებული გზებია.

### 4.2 `data/plan.geojson`

ერთი `FeatureCollection`, სამი ფენა `layer` ატრიბუტით გარჩეული. რეპოში იკომიტება
(სტატიკური საიტია, build-პროცესი არ გვაქვს).

| `layer` | გეომეტრია | წყარო | ატრიბუტები |
|---|---|---|---|
| `plot` | Polygon | `კედრის_ქუჩა_ნაკვეთები.geojson` | `cad`, `adr_num`, `street`, `area` |
| `building` | Polygon | OSM | `osm_id` |
| `road` | LineString | OSM | `osm_id`, `name`, `name_src`, `class` |

`purpose`, `note`, `street_src`, `address` **არ გადმოდის** — ნახაზზე არ ჩანს და
ჰერო ავტორიზაციამდე ისე უნდა იტვირთებოდეს, რომ ზედმეტი არაფერი ეწეროს.
სახელები და ტელეფონები აქ არასოდეს ხვდება — ისინი მხოლოდ სერვერიდან, ტოკენით მოდის.

მოსალოდნელი ზომა: ~200 KB. `git`-ისთვის მისაღებია.

### 4.3 გზების სახელები — `tools/plan_lib.py`

OSM-ში სახელი მხოლოდ ხუთ ხაზს აქვს — ოთხი განსხვავებული სახელი: `ლეო კვაჭაძის ქუჩა`
(ორი ხაზი), `კედრის ქუჩა`, `კედრის I გასასვლელი`, `კედრის II გასასვლელი`. ჩვენ კი
რვა ქუჩა გვაქვს. დანარჩენს
ნაკვეთების მონაცემიდან მივაწერთ.

```python
assign_street_names(roads, plots, radius_m=40, min_votes=3, min_share=0.6)
```

წმინდა ფუნქცია, ქსელის გარეშე, ტესტირებადი:

1. თითოეული უსახელო გზისთვის აიღება ნაკვეთები, რომელთა ცენტროიდიც გზის ხაზიდან
   `radius_m`-ზე ახლოსაა
2. ხმები ითვლება `street`-ის მიხედვით
3. თუ გამარჯვებულს **≥3 ხმა** და **≥60%** აქვს — მიეწერება, `name_src: "დაშვებული"`
4. სხვა შემთხვევაში გზა **უსახელო რჩება**

OSM-ის საკუთარი სახელი ყოველთვის იმარჯვებს, `name_src: "osm"`.

**რატომ ასე მკაცრად:** მცდარი ქუჩის სახელი ნახაზზე უარესია, ვიდრე ცარიელი გზა —
მეზობელი მას ენდობა. ზღვარს ვერ გადალახა → არაფერი წერია.

შედეგს **თვალით შევამოწმებ** გაშვების შემდეგ და ანგარიშში დავწერ, რომელ გზას
რომელი სახელი მიეწერა.

## 5. რენდერი

### 5.1 წმინდა ფუნქციები — `js/lib.js`

არსებული `WebLib`-ს ემატება (ტესტირებადი, DOM-ის გარეშე):

| ფუნქცია | აბრუნებს |
|---|---|
| `projectPoint(lon, lat)` | `{x, y}` — Web Mercator, უგანზომილებო |
| `geoBounds(features)` | `{minX, minY, maxX, maxY}` პროექციის სივრცეში |
| `fitViewBox(bounds, padding)` | `"minX minY width height"` |
| `polygonCentroid(ring)` | `{x, y}` — ფართობით შეწონილი, წარწერის საყრდენი |
| `pathFromRings(rings)` | SVG `d` ატრიბუტი |

**პროექცია.** Web Mercator, არა უბრალო `lon/lat` — ამ განედზე (41.7°) გრძედის
გრადუსი განედის გრადუსზე ~25%-ით მოკლეა და ნახაზი გაბრტყელებული გამოვიდოდა.

### 5.2 `js/plan.js`

ერთი მოდული, ორი რეჟიმი:

```js
PlanView.render(container, { mode: 'hero' })
PlanView.render(container, { mode: 'interactive', plots, user })
```

**ფენების რიგი** (SVG `<g>`, ქვემოდან ზემოთ):

1. `plan-roads-casing` — გზის მუქი კიდე
2. `plan-roads-fill` — გზის ქაღალდისფერი სხეული
3. `plan-plots` — საკადასტრო კონტური, hairline
4. `plan-buildings` — ნაგებობის მუქი ბლოკი
5. `plan-labels-address` — მისამართის ნომერი ნაკვეთის ცენტროიდზე
6. `plan-labels-street` — ქუჩის სახელი `<textPath>`-ით გზის ღერძზე

**`hero`** — `data/plan.geojson`-იდან, ინტერაქციის გარეშე, `aria-hidden="true"`,
გვერდით კი ვიზუალურად დამალული ტექსტური აღწერა screen reader-ისთვის. ფერადი კოდირება გამორთულია —
ერთი მელნის ტონი, რომ ეკრანი წყნარი დარჩეს.

**`interactive`** — ფონი (გზები, შენობები) იმავე სტატიკური ფაილიდან; ნაკვეთები კი
**სერვერიდან** მოსული ცოცხალი გეომეტრიით, `cad`-ით შეწყვილებული. სრულად ნარჩუნდება
დღევანდელი ქცევა: ქუჩების ფერადი პალიტრა და ლეგენდა, პოპაპი, რედაქტირების ღილაკი
(`data-edit` event delegation-ით), წერტილოვანი fallback უპოლიგონო ნაკვეთისთვის,
„რუკაზე არ ჩანს" სია.

**pan/zoom.** `viewBox`-ის მანიპულაცია: wheel → მასშტაბი კურსორის ირგვლივ,
drag → გადაადგილება, ორმაგი დაწკაპუნება → საწყისი ხედი. ~120 სტრიქონი.
ხაზები `vector-effect="non-scaling-stroke"`-ით მუდმივი სისქისაა; წარწერების
`font-size` ყოველ zoom-ზე გადაითვლება, რომ ეკრანზე მუდმივი დარჩეს.

### 5.3 Leaflet-ის ამოღება

`index.html`-იდან ორი CDN ტეგი (`leaflet.css`, `leaflet.js`) ქრება, `js/map.js`
`js/plan.js`-ით იცვლება. `UI.showTab('map')` ისევ იმავე ტაბს ხსნის —
`MapView.refresh()`-ის ადგილს `PlanView.refresh()` იკავებს.

**ODbL ატრიბუცია სავალდებულო რჩება.** გეგმის ქვეშ პატარა წარწერა:
`გზები და ნაგებობები: © OpenStreetMap-ის მონაწილეები (ODbL)`

საკადასტრო კონტურების წყარო ჩვენივე `კედრის_ქუჩა_ნაკვეთები.geojson`-ია; მისი

საჯაროდ მიეწერება.
