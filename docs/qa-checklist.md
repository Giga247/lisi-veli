# ხელით შესამოწმებელი სცენარები

გაიარეთ დეპლოის შემდეგ. ავტომატური ტესტები (`node --test tests/*.test.js`)
მხოლოდ `js/lib.js`-ის სუფთა ლოგიკას ფარავს — უფლებები, ბაზა და
ინტერფეისი აქ მოწმდება.

**ტელეფონზე გაიარეთ, არა კომპიუტერზე.** მომხმარებელთა უმეტესობა იქიდან
შემოდის და განლაგებაც მისთვისაა აგებული.

## 1. შესვლა

- [ ] გვერდი იხსნება, ჩანს უბნის ნახაზი და ღილაკი „Google-ით შესვლა"
- [ ] შესვლის შემდეგ ჩანს მთავარი: რუკა, პროექტები, სია
- [ ] გვერდის გადატვირთვა შესვლას არ ითხოვს — სესია რჩება
- [ ] „გასვლა" აბრუნებს შესვლის ეკრანზე

**ახალი მომხმარებელი** (სხვა Google ანგარიშით):

- [ ] შესვლისთანავე ხედავს „მოთხოვნა გაგზავნილია", არა რეესტრს
- [ ] ადმინთან „ადმინი" ტაბში ჩანს ახალ მოთხოვნად
- [ ] როლის მინიჭების შემდეგ (გვერდის გადატვირთვით) ხედავს რეესტრს

## 2. მთავარი გვერდი

- [ ] რუკა **ქუჩების ფერებია**, არა სტატუსების
- [ ] ნაკვეთებს **თეთრი კანტი** აქვთ
- [ ] ნაკვეთზე შეხებით ქვემოდან ამოდის ბარათი: სახელი, მისამართი,
      ფართობი, საკადასტრო კოდი
- [ ] იგივე ბარათი იხსნება სიიდანაც
- [ ] ბარათი იკეტება ფონზე დაჭერით და Escape-ით
- [ ] ძებნა და ქუჩის ჩიპები სიას ფილტრავს

## 3. ტელეფონის ხილვადობა

**ეს ყველაზე მნიშვნელოვანი შემოწმებაა.**

მაცხოვრებლის ანგარიშით (`member`, არცერთი პროექტის ხაზინდარი არაა):

- [ ] ბარათში „დარეკვა" ღილაკი **არ ჩანს**
- [ ] ბრაუზერის კონსოლში `PLOTS.filter(p => p.phone).length` აბრუნებს **0**-ს

ეს მეორე პუნქტი კრიტიკულია: თუ რიცხვი ნულზე მეტია, ნომრები ბრაუზერამდე
მოდის და მხოლოდ ეკრანზეა დამალული — ეს დაცვა არ არის.

მოდერატორის ან ადმინის ანგარიშით:

- [ ] „დარეკვა" ჩანს და ტელეფონს ხსნის

## 4. რედაქტირება

მოდერატორით ან ადმინით:

- [ ] ბარათში ჩანს „რედაქტირება"; მაცხოვრებელთან — არა
- [ ] ტელეფონის ველში `599123456` ინახება როგორც `+995599123456`
- [ ] `12345` აგდებს ქართულ შეცდომას და ფორმა ღია რჩება
- [ ] შენახვის შემდეგ სია მაშინვე ახლდება

**კონკურენტული ცვლილება** (ორი ბრაუზერი, ერთი ნაკვეთი):

- [ ] მეორე შენახვა აგდებს „ჩანაწერი სხვამ შეცვალა, გადატვირთეთ გვერდი"

## 5. პროექტის შექმნა

ადმინით ან მოდერატორით:

- [ ] „+ ახალი" ხსნის ფორმას
- [ ] ქუჩის მონიშვნა რთავს მის ყველა ნაკვეთს; „ყველა" შუალედურზე გადადის
- [ ] თანხა `123` ჯამის სტრიქონში ჩანს როგორც `125 ₾` (5-იან ნაბიჯზე)
- [ ] მრგვალი `100` **მიიღება** — რეგრესია: `step="5"` მას უარყოფდა
- [ ] შექმნის შემდეგ პროექტი `მზადდება` სტატუსშია, ბანერით

მაცხოვრებლით:

- [ ] „+ ახალი" ღილაკი არ ჩანს

## 6. დამტკიცება

- [ ] მოდერატორთან „დამტკიცება" არ ჩანს
- [ ] ადმინთან პირველი დაჭერა ღილაკს აწითლებს და დადასტურებას ითხოვს
- [ ] მეორე დაჭერის შემდეგ სტატუსი `მიმდინარე`-ა და ჩნდება ნაკვეთების სია
- [ ] ვალდებულებების რაოდენობა არჩეულ ნაკვეთებს ემთხვევა

## 7. პროექტის გვერდი

- [ ] რუკა **სტატუსების ფერებია**
- [ ] ნაკვეთის მწკრივზე დაჭერით იხსნება ფანჯარა
- [ ] მაცხოვრებელიც ხსნის ფანჯარას (ხედავს სტატუსს, ვერ ცვლის)
- [ ] მოდერატორთან ჩანს **ხუთი** სტატუსი და „დარეკვა"
      („გადახდილია" ჩიპებში არ არის — ის ბოლოს ჩამრთველია)
- [ ] მარჯვენა კუთხეში ✎ (ნაკვეთის რედაქტირება) და ✕ — ამ რიგით
- [ ] ✎ მაცხოვრებელს **არ უჩანს**
- [ ] ✎ ხსნის იმავე ფორმას, რასაც მთავარი სია; შენახვის შემდეგ
      პროექტის ბარათში ახალი სახელი ჩანს
- [ ] „შენახვაზე" ამოდის პოპაპი, სადაც ჩამოთვლილია რა იცვლება
- [ ] პოპაპში „არა" არაფერს ინახავს
- [ ] სტატუსის შეცვლა ფერს რუკაზეც ცვლის

## 8. გადახდა

- [ ] ჩამრთველი „გადახდილია" ბარათის **ბოლოშია**, წილის ოდენობით
- [ ] **მოდერატორს ჩამრთველი საერთოდ არ უჩანს** — მხოლოდ ხაზინდარს და ადმინს
- [ ] ჩართვა + შენახვის დადასტურება → სტატუსი ავტომატურად **„გადახდილია"**
- [ ] გამორთვა + შენახვა → გადახდა უქმდება და სტატუსი ჩიპებში
      მონიშნულზე ბრუნდება
- [ ] ხაზინდარს, ვისაც სტატუსის ცვლა არ შეუძლია, ჩიპები მხოლოდ
      ჩამრთველის გამორთვისას უჩნდება
- [ ] „შემოვიდა" იზრდება, „აკლია" მცირდება
- [ ] ისტორიაში ჩანს ვინ ჩაწერა და როდის

**ნამეტი:** თუ შემოსული ბიუჯეტს გადააჭარბებს —

- [ ] ბოლო სვეტი „აკლია"-დან „ნამეტი"-ზე გადადის

## 9. ადმინი

- [ ] „მომხმარებლები" ჩამონათვალში ჩანს ყველა
- [ ] როლის შეცვლა მუშაობს
- [ ] საკუთარი როლის შეცვლა უარიყოფა
- [ ] „ჟურნალში" ჩანს ბოლო ცვლილებები, ავტორითა და დროით
